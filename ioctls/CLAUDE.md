# ioctls/ — Per-Subsystem ioctl() Argument Generators

Registry of kernel ioctl-driven subsystems Trinity fuzzes through the `ioctl()` syscall. One file per subsystem (device driver, virtualization interface, filesystem control plane, etc), except where a subsystem's ioctl surface was large enough to carve one class per file behind an internal header; each group declares its ioctl command table and, optionally, hand-rolled argument sanitisers for commands whose args are structs. `syscalls/ioctl.c` picks a group at dispatch time; groups don't call each other.

## Files

Core registry/dispatch (not a per-device group):
- `ioctls.c` — group registration table, fd→group matching (`find_ioctl_group`), the tiered arg-shape picker (`pick_random_ioctl` / `ioctl_arg_for_request`), `dump_ioctls()`. No `REG_IOCTL_GROUP` — this *is* the registry.

Largest / structurally distinct per-device files:
- `drm.c` — DRM core plus vendor extensions (i915, nouveau, radeon, exynos); defines fallback structs/macros for nouveau ioctls not present in all kernel header versions (`DRM_IOCTL_NOUVEAU_GETPARAM` etc, guarded by `#ifndef`).
- `btrfs.c` — btrfs filesystem ioctls (as opposed to `btrfs-control.c`, the `/dev/btrfs-control` device-manager group).
- `vhost.c` — vhost-net/vsock/scsi/vdpa control ioctls.
- `firewire.c` — IEEE1394 character device ioctls.
- `cdrom.c` — CDROM/ATAPI command family.
- `binder.c` carries its own copy of `<linux/android/binder.h>`-equivalent definitions (`flat_binder_object`, `binder_write_read`, etc) inline, since the header isn't part of the standard kernel-headers package trinity builds against.

## Key design decisions

1. **One `struct ioctl_group` per file, self-registered via constructor.** `IOCTL(x)` macro (`include/ioctls.h`) builds `{.request = x, .name = "x"}` table entries; `REG_IOCTL_GROUP(grp)` expands to a `__attribute__((constructor))` function that calls `register_ioctl_group(&grp)` at load time, so files never need to be listed anywhere centrally — dropping a new `.c` file with a `REG_IOCTL_GROUP` line is the entire integration.
2. **Group matching is fd-based, two paths.** `find_ioctl_group()` first tries every registered group's optional `fd_test(fd, &stbuf)` callback (used when devname matching is ambiguous or the fd is anonymous — e.g. `pidfd_fd_test()` walks the `OBJ_FD_PIDFD` object pool rather than checking `/proc/devices`). The four groups that name an `fd_class` (pidfd, socket, epoll, perf_event) walk the parent's pool of the class and also probe the child's own with `find_local_object_by_fd()`: `get_typed_fd()` serves the parent's alone, but the fd pick hands `ioctl()` the child's recent returns, and those sit only in its local pool. If no `fd_test` claims the fd, it falls back to matching `devtype` (`DEV_CHAR`/`DEV_BLOCK`/`DEV_MISC`) plus device name against each group's `devs[]` list (resolved via `map_dev()`).
3. **No struct_catalog/ or args/ dependency.** Unlike other struct-producing subsystems in the tree, ioctl arg structs here are filled by hand: a `sanitise_<name>()` function calls `get_writable_struct(sizeof(*s))`/`get_writable_address(size)`, `memset()`s the whole struct to zero, then stamps only the fields the author decided matter (bounded random values, valid-looking enums, etc), leaving the rest zeroed rather than catalog-random. The "memset before field stores" half of this pattern is a convention nothing enforces statically; it matters because `get_writable_struct()` returns recycled pool memory that can leak previous-syscall residue back to the kernel (or be read as attacker-influenced-but-unintended field values) if left unzeroed.
4. **Three-tier arg-shape picker in `ioctls.c` (`ioctl_arg_for_request`)**, run before any per-group custom sanitiser, then overridden per-command where a custom sanitiser exists:
   - Tier 1 (decoded): if the request was built with `_IO*()` and carries a non-`_IOC_NONE` direction, trust `_IOC_SIZE()`/`_IOC_DIR()` for buffer size and read/write direction; seed with random bytes for `_IOC_WRITE`.
   - Tier 2 (EFAULT-probe cache, `efault_cache.c`): for legacy raw-constant ioctls (TCGETS-style, sockios) with no shape info in the request number, call the ioctl once with a bogus pointer arg and classify by errno (`EFAULT`→pointer, `EINVAL/ENOTTY/ENOSYS/0`→scalar, `EBADF/ENXIO`→unknown/mismatched fd). Verdict is cached fleet-wide in shm, keyed by `(group_idx, request)`, since the kernel's dispatch table is process-independent. Probes twice with different bogus values and only commits if both agree.
   - Tier 3 (legacy 50/50): coin-flip between a random scalar and a writable page, used when Tier 2 is inconclusive or the group opted out of probing.
5. **EFAULT-probe opt-out list** (`efault_cache.c`, `efault_optout_devs[]`): groups whose ioctls allocate real kernel state on the dispatch path *before* arg validation — `vhost-{net,vsock,scsi,vdpa}`, `iommu`, `vfio` and `loop-control`, matched by devname — skip Tier 2 entirely to avoid leaking rings/containers/loop devices on every probe.
6. **Post-sanitise scrub against shared regions.** `pick_random_ioctl()` and `syscalls/ioctl.c`'s `sanitise_ioctl()` both call `avoid_shared_buffer_out()` on `a3`/`a4`/`a5`/`a6` — custom sanitisers that overwrite `a3` with their own struct pointer are covered by the second scrub in `syscalls/ioctl.c`, run unconditionally after the group's `.sanitise()` returns, so a struct pointer accidentally aliasing trinity's shm bookkeeping (childdata/stats/kcov buffers) can't be handed to the kernel for `copy_to_user`.
7. **Return type is published per cmd.** `syscall_ioctl` has no static `.rettype`. A group sanitiser that picks a cmd whose return value is the new fd, not one written into the arg struct, sets `rec->rettype = RET_FD`, and `effective_rettype()` hands that to the fd accounting and the retfd validator. Today that is pidfd's ten namespace getters, `VFIO_GROUP_GET_DEVICE_FD`, `VDUSE_IOTLB_GET_FD`/`_FD2` and `DRM_IOCTL_I915_PERF_OPEN`; `tests/ioctl_sanitise_test.c` pins the list. `sanitise_ioctl()` clears it unless `find_ioctl_group()` claimed the fd: a group drawn at random sends its cmd to a driver that owns the return value. `post_ioctl()` then owns what a pidfs getter returns, through `pool_returned_fd()` (`fds/fds-pool.c`): a capped local pool that destroys its oldest object to make room. The cmd slot is rewritten after the sanitiser published `RET_FD` (a RedQueen pin, a chain substitution), and any such rewrite resets the type to `RET_NONE`. So the return may be a plain 0 under some other cmd, or the fd a getter made, and `post_ioctl()` does not read the type: it pools or closes a number only once `pidfd_ns_getter()` accepts the cmd as the kernel reads it (an `unsigned int`) and `fstatfs()` says the number is a file on nsfs. A number that fails either check, and a stdio or protected number, is left alone, open and unpooled; only what the pool refuses after that is closed. The vfio, vduse and i915 cmds publish `RET_FD` too and stay unowned. Only the pidfd getters can succeed as a child generates them. pidfs refuses a non-zero arg once it has the task (`pidfd_ioctl()` in `fs/pidfs.c`), so three calls in four pass 0, and the group claims the pidfds `pidfd_open()` made as well as the parent's, which names pid 1 and fails the getters' ptrace check. The other three name something a child cannot have: a device by name in the group's iommu group (`vfio_group_ioctl_get_device_fd()`), an iova mapping a vDPA bus consumer made in a domain only `vdpa_dev_add()` creates (`vduse_dev_iotlb_entry()`), and an OA metrics config on Intel hardware (`i915_perf_open_ioctl()`); their args stay as generated.

## Integration points

- `syscalls/ioctl.c` — the actual `ioctl()` syscall entry (`sanitise_ioctl()`): picks a group via `get_random_ioctl_group()` (1-in-100, deliberately mismatching fd and group to explore misuse); else, on 1 in 16 of the rest, draws a group first with `get_random_fd_class_ioctl_group()` and swaps an fd of its `fd_class` into `a1` (`get_typed_fd()`, confirmed by the group's `fd_test`; no such fd leaves the call to the next pick, and `ioctl_group_first` counts the ones that land); else via `find_ioctl_group(rec->a1)`. It then calls `grp->sanitise(grp, rec)` and re-scrubs `a3`.
- `include/ioctls.h` — A group whose `fd_test` claims exactly the fds of one typed-fd pool also sets `fd_class` (pidfd, socket, epoll and perf_event today), which is what lets `sanitise_ioctl()` draw it before the fd. No other group qualifies. `vfs_fd_test` claims seven pools (pipe, /dev, /proc, /sys, testfile, memfd, timerfd), so the fd pick already reaches it through any of seven providers, and a class for it would take a fifth of the group-first draws from the four groups that each hang off one small pool. `atm_fd_test` claims only the `PF_ATMPVC` sockets, so a socket class would mostly miss. `userfaultfd_fd_test` and `seccomp_notif_fd_test` claim small pools, but `get_typed_fd()` serves no class for either, and a new argtype is more than a field on the group. The rest match a device node (nbd, loop, joystick, random), a readlink target (gpio, dmabuf) or the testfile pool (ext, btrfs), which no argtype names.
- `fds/scratch_block.c` — `loop.c`'s status-write sanitiser matches the fd against the loop entries published in `shm->isolation.scratch_block[]` and keeps `LO_FLAGS_AUTOCLEAR` set on a `LOOP_SET_STATUS(64)` aimed at one of those devices.
- `utils/shm.c`/`shm` — backs both the EFAULT-probe cache (`shm->ioctl_efault_cache[]`, lock-free CAS insert) and per-group dispatch counters some groups bump (e.g. `btrfs.c` increments `shm->stats.btrfs_ioctls_dispatched`).
- `syscalls/io_uring/io_uring_register.c` — references `pick_random_ioctl()`'s arg-scrub ordering in a comment, implying a parallel (not shared) arg-shape convention for `io_uring_register`'s own opcode table.

## Areas of attention

1. **`vfio.c` and `iommufd.c` are among the most heavily hand-tuned groups in this directory** Both are `_IO()`-declared (no encoded size or direction), so Tier-1 `_IOC_SIZE` carries no signal and would hand the kernel a random-shaped buffer; the sanitisers replace that path entirely and stamp each struct's `argsz`/`size` field in-band.
3. **EFAULT-probe side effects are opt-out by devname list, not derived from the kernel.** `efault_optout_devs[]` in `efault_cache.c` is a manually maintained list; a new group whose dispatch path allocates kernel state before arg validation (a new vhost transport, a new virtualization ioctl set) silently leaks that resource on every EFAULT probe until someone notices and adds it to the list, and a group matched only through `fd_test` has no devname to list.
4. **No shared struct-generation infrastructure.** Every `sanitise_*` function hand-codes field values (bounded `rnd_modulo_u32()` calls, `RAND_BOOL()` flag picks); there is no catalog-driven or reflection-based struct filler for this directory (`grep -rn struct_catalog ioctls/` — zero hits), so field coverage and bounds-plausibility depend entirely on the judgment of whoever wrote each `sanitise_*` function, and are not automatically kept in sync with kernel struct changes.
