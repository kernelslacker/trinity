# net/netlink/nfnl/ — Netfilter Netlink Subsystem Grammars

## Notes
- wired by extern struct, collected by `subsystems.c`. Link-time, no path coupling.
- `nfnetlink_rcv()` runs `netlink_net_capable(skb, CAP_NET_ADMIN)` on every message before it looks at the subsystem, so every command, GET and dump requests included, is answered `-EPERM` unless both the socket's opener and the sender hold CAP_NET_ADMIN in the user namespace that owns the socket's netns. The policy parse and the handlers sit behind that test and are reached only by a child that passes it; the cthelper and osf handlers then also require `capable(CAP_NET_ADMIN)`, the initial user namespace. Subsystem files name only what is specific to them.
- `nfnetlink_rcv_msg()` and the batch path parse the top-level attributes with the liberal `nla_parse_deprecated()` against the callback's policy: an id past `attr_count` is dropped, an id in an untyped slot is accepted unchecked, and a typed slot is length-checked. A flat-table attribute the picked command's policy lacks is therefore ignored (a strict-validating genl op answers `-EINVAL`), while one whose id another namespace of the same table types differently meets that type.
- A cmd whose policy is not the subsystem's, or whose handler needs attributes its siblings' do not, carries its own table in `nfnl_cmd_grammar.attrs`, and `nfnl_cmd_attrs()` (`subsystems.c`), which `pick_spec_table()` asks with the cmd byte of `nlmsg_type`, hands it back; a cmd with none, or one the grammar does not list, draws from the subsystem's flat table. The liberal parse above means a per-cmd table never makes the kernel refuse a request: an id its policy lacks is ignored anyway. What it decides is what a request carries, so that a request draws from the namespace its cmd reads, not from a union whose ids mean something else to another cmd.
- Each nftables command draws from a table of its own, `nft_*_attrs[]` in `nftables.c`, that holds what its handler reads of its namespace's policy and marks `.required` what the handler returns early without. The namespaces number their attributes from 1 each, so no one table serves them. `nft_table_lookup()` and its kin answer a missing name `-EINVAL`, so a request without one never reaches the main path. The handles are left out of every table: the kernel numbers objects itself, so a handle drawn at random matches none, and a handler that is given one looks the object up by it in place of its name. A delete whose name is optional leaves it unmarked, since without a name or a handle it acts on everything. `NFT_MSG_GETGEN`, which `nf_tables_cb[]` gives no policy and an `attr_count` of 0, reads no attribute and has no table, so it takes the legacy random attributes.
- Table and chain. NEWTABLE and GETTABLE mark the name; DELTABLE and DESTROYTABLE do not, since with neither name nor handle they flush the family. The chain commands mark the table and the chain's name, and NEWCHAIN's `NFTA_CHAIN_HOOK` and `NFTA_CHAIN_COUNTERS` have tables of their own, because a base chain needs both a hook number and a priority, and a counter pair both counters (`nft_chain_parse_hook()`, `nft_stats_alloc()`). Its `NFTA_CHAIN_POLICY` is `NF_DROP` or `NF_ACCEPT`, and its `NFTA_CHAIN_TYPE` is one of `filter`, `nat` and `route`, which `nf_tables_chain_type_lookup()` finds without a `request_module()`.
- Rule. NEWRULE, GETRULE and GETRULE_RESET mark the table and the chain, DELRULE and DESTROYRULE the table alone, since without a chain they delete the rules of every chain in it. The handle, position and chain id of a rule are left out, like the other handles: each names a rule or a chain by a number a draw cannot know, and a handle turns NEWRULE from adding a rule into replacing one. NEWRULE's `NFTA_RULE_EXPRESSIONS` has no table of its own, and every request that carries it is refused: an element must be of type `NFTA_LIST_ELEM` and name an expression, which nothing in the rule's table makes.
- Set and set element. NEWSET marks the four attributes that `nf_tables_newset()` answers `-EINVAL` without, the table, the name, `NFTA_SET_KEY_LEN` and `NFTA_SET_ID`, and draws the words it bounds from what it takes: `NFTA_SET_KEY_LEN` and `NFTA_SET_DATA_LEN` are `NLA_KIND_BE32_RANGE` from 1 to `NFT_DATA_VALUE_MAXLEN`, and `NFTA_SET_POLICY` is one of the two set policies. The attributes that need a flag beside them (`NFTA_SET_DATA_TYPE` the map flag, `NFTA_SET_TIMEOUT` the timeout flag) are drawn without regard to it, and `NFTA_SET_DESC`, `NFTA_SET_EXPR` and `NFTA_SET_EXPRESSIONS` are not in the table, being nests the grammar cannot build yet. GETSET, DELSET and DESTROYSET mark the table and the name. The set-element commands mark the table, the set and `NFTA_SET_ELEM_LIST_ELEMENTS`, except that DELSETELEM and DESTROYSETELEM, which empty the set without elements, leave the elements unmarked. ELEMENTS is an `NLA_KIND_NESTED_ARRAY` whose elements have a table of their own: adding one reads all of `nft_set_elem_policy` and needs a `NFTA_SET_ELEM_KEY` unless its flags say catch-all, and getting or deleting one reads the key, the flags and `NFTA_SET_ELEM_KEY_END`. A key is a nest that must hold `NFTA_DATA_VALUE`, whose length `nft_value_init()` holds to the set's `NFTA_SET_KEY_LEN`; nothing in the draw knows that length, so about one key in 64 has it. An element's `DATA`, `EXPR` and `EXPRESSIONS` stay untyped.
- Object and flowtable. The object commands mark the table, the name and `NFTA_OBJ_TYPE`, and NEWOBJ its `NFTA_OBJ_DATA` as well, since `nf_tables_newobj()` answers `-EINVAL` without the type, the name or the data. The type is `NLA_KIND_BE32_RANGE` from the counter to `NFT_OBJECT_MAX`: a number that no object type has makes `nft_obj_type_get()` queue a `request_module()` for `nft-obj-<type>`. DATA stays a bare nest, its children drawn from the object's own table, since the policy it is parsed against is the type's and nothing ties it to the type drawn. The flowtable commands mark the table and the name, and NEWFLOWTABLE `NFTA_FLOWTABLE_HOOK`, whose table holds the hook number, only `NF_NETDEV_INGRESS` being one `nft_flowtable_parse_hook()` takes, and the priority, both marked since it answers `-ENOENT` without either. The devices are left out, a flowtable without any being accepted, and so is a HOOK in a delete, which takes devices out of the flowtable instead of deleting it.
- 21 of the 32 nftables commands (the NEW, DEL and DESTROY ones, marked `.batch` in `nftables_cmds[]`) are `NFNL_CB_BATCH` callbacks. `nfnetlink_rcv_msg()` answers one sent alone `-EINVAL`, after it has parsed the attributes; `nfnetlink_rcv_batch()` takes only batch callbacks of the subsystem that BEGIN names in `res_id`, answers any other message in the batch `-EINVAL`, and aborts instead of committing if any command failed. `build_nfnl_batch()` (`net/netlink/msg-core.c`) writes BEGIN, one to four batch callbacks of that subsystem and END, leaving END off one batch in eight: the walk then ends with the buffer, and `nfnetlink_rcv_batch()` aborts with `NFNL_ABORT_VALIDATE` if no command failed and `NFNL_ABORT_NONE` if one did. BEGIN carries no `NFNL_BATCH_GENID`, which the kernel would hold to the current generation.
- A scalar a policy bounds with `NLA_POLICY_MASK` (the `*_FLAGS` words) is declared `NLA_KIND_BE16_MASK` or `NLA_KIND_BE32_MASK`, with the policy's own mask in `max_len`; the netfilter policies read these in network byte order. `NLA_KIND_BE32_RANGE` takes an inclusive range in `min_len` and `max_len`: from 0 it is an `NLA_POLICY_MAX`, and it also serves a word that the handler bounds and reads with `ntohl()` where the policy leaves it a plain `NLA_U32`. `spec_fill_bounded()` (`net/netlink/msg-attr-spec.c`) draws a subset of the mask bits, or a number in the range, and leaves one draw in eight random bytes so the reject arm still sees traffic. The expression policies behind `NFTA_RULE_EXPRESSIONS` hold many more such scalars, which no flat-table child targets.
- A scalar whose handler, not its policy, narrows it to a few values is declared `NLA_KIND_U8_ONEOF`, `NLA_KIND_BE16_ONEOF` or `NLA_KIND_BE32_ONEOF`, with the values in `oneof` and `n_oneof`; the kind fixes the width and byte order the handler reads it in, and `spec_fill_bounded()` picks one value and leaves one draw in eight random bytes, as for the bounded kinds. cttimeout's `CTA_TIMEOUT_L4PROTO` lists ICMP, TCP, UDP, GRE, ICMPv6, SCTP and 255, the numbers `nf_ct_l4proto_find()` has a tracker for (the GRE, ICMPv6 and SCTP ones when the kernel is built with them); NEW, DEFAULT_SET and DEFAULT_GET answer any other `-EOPNOTSUPP`. `CTA_TIMEOUT_L3PROTO` lists IPv4 and IPv6: no cttimeout handler checks it, but NEW with `NLM_F_REPLACE` and `nf_ct_set_timeout()` compare it. nft_compat's `NFTA_COMPAT_TYPE` lists 0 and 1: `nfnl_compat_get_rcu()` takes `htonl(1)` for a target and any other number for a match. Its `NFTA_COMPAT_REV` lists 0 to 3, the revisions of the extensions the grammar names, though the policy takes up to 255: `xt_find_revision()` has an extension only at the revision it registered and answers any other `-EPROTONOSUPPORT`. `NFNLA_HOOK_HOOKNUM` lists the five inet hooks: its policy caps it at 255, but `nfnl_hook_entries_head()` refuses a number past the family's hook array, `NF_INET_NUMHOOKS` long for IPv4, IPv6 and bridge. The hook numbers of `nf_tables_api.c` have that shape too (`nft_chain_parse_hook()` takes `NFTA_HOOK_HOOKNUM` below `NFT_MAX_HOOKS` and in the chain type's `hook_mask`, and `NFTA_CHAIN_HOOK`'s table draws it from the same five inet hooks; `nft_flowtable_parse_hook()` takes `NFTA_FLOWTABLE_HOOK_NUM` only as `NF_NETDEV_INGRESS`, which `NFTA_FLOWTABLE_HOOK`'s table draws).
- `NLA_KIND_STRING_ONEOF`, with its names in `words` and `n_words`, is the string counterpart of those scalars: it is for a name the handler looks up in a registry that holds several, where `NLA_KIND_STRING_WORD` is the one word that names must agree on. A name that is not in the registry can cost the kernel a `request_module()`, one for each name drawn at random. `spec_payload_len()` (`net/netlink/msg-attr-spec.c`) picks a word and `spec_fill_payload()` fills one of that length, and one draw in eight is random lowercase letters as long as a word, so the lookup that misses still sees traffic.
- nf_tables finds a table by its family and name together and everything in it by name, so a command reaches the main path of its handler only if it names what an earlier command made. `build_nfnl_batch()` therefore picks one `nfgen_family` from the grammar's `families` (the six `nft_supported_family()` takes) and `gen_nfnl_body()` keeps it on each command seven times in eight, and the name attributes, ids 1, 2 and 3 in every namespace and all `NLA_STRING`, are `NLA_KIND_STRING_WORD`: they carry the one word `nft_word` seven draws in eight and random lowercase letters of its length otherwise. The word does not change from batch to batch, so the tables that batches commit recur rather than pile up. `NFTA_SET_ELEM_OBJREF` stays random.
- cttimeout's five commands each have a table of their own, since they read different parts of `cttimeout_nla_policy`. NEW marks the name, `CTA_TIMEOUT_L3PROTO`, `CTA_TIMEOUT_L4PROTO` and `CTA_TIMEOUT_DATA`, which `cttimeout_new_timeout()` answers `-EINVAL` without; GET marks the name, which a dump does not need; DELETE does not, since without a name it deletes every timeout; DEFAULT_SET marks L4PROTO and DATA, DEFAULT_GET L3PROTO and L4PROTO, and neither reads a name. DATA's table is 11 `NLA_U32` timeouts numbered from 1, TCP's policy being the longest of the L4 ones, so one table serves them all, an id past a policy's last being skipped.
- cttimeout's `CTA_TIMEOUT_NAME` is `NLA_KIND_STRING_WORD`, the one word `cttimeout_word`: GET, DELETE and the `NLM_F_REPLACE` arm of NEW find a timeout by `strncmp()`ing its name, and a NEW with a name drawn at random makes another timeout each time instead of meeting the last. The word is short of `CTNL_TIMEOUT_NAME_MAX`, which the policy's `NLA_NUL_STRING` allows, and `check_word_name()` holds every declaration of the name to it.
- nfacct's three commands each have a table of their own. NEW marks `NFACCT_NAME`, which `nfnl_acct_new()` answers `-EINVAL` without, and reads the counters, the flags and the quota; GET marks the name, which a dump does not need, and holds the `NFACCT_FILTER` nest a dump reads, whose mask and value `nfnl_acct_start()` wants both of; DEL does not mark the name, since without one it deletes every object. The name is `NLA_KIND_STRING_WORD` for the reason cttimeout's is: GET, DEL and a NEW that meets an object find it by `strncmp()` on the name, and a name drawn at random would make one more object on each NEW.
- hook's one command, `NFNL_MSG_HOOK_GET`, has a table of its own that holds the two attributes its handler reads: `NFNLA_HOOK_HOOKNUM`, marked since `nfnl_hook_get()` answers `-EINVAL` without it, and `NFNLA_HOOK_DEV`, which `nfnl_hook_dump_start()` reads only for `NFPROTO_NETDEV` and so is not marked. The priority, the function name and the module name are what a reply carries, no handler reads them, and none is drawn. The request is served only with a dump bit. Its `families` are the five `nfnl_hook_entries_head()` takes, which a lone message draws from as a batch would, `NFPROTO_NETDEV` among them, the one family that reads DEV, which names lo.
- cthelper's three commands have tables of their own. NEW marks the name and `NFCTH_TUPLE`, which `nfnl_cthelper_new()` answers `-EINVAL` without, and `NFCTH_POLICY` and `NFCTH_PRIV_DATA_LEN`, which `nfnl_cthelper_create()` does; updating a helper that has the name and tuple already takes those two as optional and answers `-EBUSY` to either unless it matches what the helper has. The tuple's `L3PROTONUM` and `L4PROTONUM` are marked, and so are the policy's `SET_NUM`, a range from 1 to the kernel's `NF_CT_MAX_EXPECT_CLASSES`, and all four SETs, since the count, which a mark cannot follow, decides how many are needed and a SET past it is passed over; each SET marks its name, its `EXPECT_MAX`, a range to `NF_CT_EXPECT_MAX_CNT`, and its timeout. GET and DEL read the name and the tuple and mark neither: without them GET answers the first helper and DEL deletes every one. The handlers find a helper by its name and tuple together, so the name, and an expectation policy's, which an update holds to the helper's, is the one word `cthelper_word`, and the tuple keeps to IPv4 and IPv6 and to TCP and UDP. `NFCTH_PRIV_DATA_LEN` is a range to the 32 bytes of `nf_conn_help`'s data, and `NFCTH_STATUS` one of the two statuses the handlers act on.
- nft_compat's one command, `NFNL_MSG_COMPAT_GET`, has its table as the command's own, with the name, `NFTA_COMPAT_REV` and `NFTA_COMPAT_TYPE` all marked, since `nfnl_compat_get_rcu()` answers `-EINVAL` without any of the three. The name is `NLA_KIND_STRING_ONEOF`, one of 14 matches and targets that `xt_find_revision()` finds for IPv4 and IPv6 (`word_slots[]` holds the list to what the xt modules register): a name it does not find costs a `request_module()` of `ipt_<name>` and its kin, which a name drawn at random would do on every call. TYPE is drawn without regard to the name, so about half of the names meet the kind they are.
- In the subsystems here a nest is a bare `NLA_NESTED`, which `nla_validate()` does not look into, except five `NLA_POLICY_NESTED_ARRAY` entries in `nf_tables_api.c` (rule, set and set-element expressions, set-desc concat, set-element list). A bare nest is parsed, if at all, by the handler: `nla_parse_nested_deprecated()` against a per-type or per-L4 sub-policy, except in ipset and ctnetlink's `CTA_FILTER`, where the strict `nla_parse_nested()` rejects a child the sub-policy lacks. `NLA_KIND_NESTED` specs are filled as `genl/CLAUDE.md` describes, one to three children from the same flat table, so the handlers see children whose ids are outer-namespace ids, unless the spec has a table of its own as `CTA_FILTER` does.
- `tests/nfnl_gen_test.c` holds the grammars to facts about the kernel's policies, through `append_specced_nlattr()` and the registry, with no socket: ctnetlink never draws `CTA_TIMESTAMP_EVENT` (`NLA_REJECT` in `ct_nla_policy`), cttimeout lists all five of its callbacks, and a table of the top-level bounded scalars, as the kernel spells them, is declared by the grammars and drawn mostly inside its bound; so is a second table of the scalars whose handlers accept a few values, each of which must be drawn. Through `netlink_gen_msg()` it checks that a buffer opening with a batch callback is put behind BEGIN most of the time and not always, that one such batch in eight has no END, that BEGIN names nftables, that only batch callbacks sit between them, that every batch callback opens a batch, and that its commands mostly share a family and name their table with the one word; the nftables name attributes, the families and the word themselves are checked against `nf_tables_api.c`'s attribute ids and `nft_supported_family()`. A word list is held to the names the kernel's registry has by `word_slots[]`; every nftables command but `NFT_MSG_GETGEN` has a table, and every command with a table has a row in `cmd_rows[]`. A cmd with a table of its own has a mirror of the policy it reads in `cmd_rows[]`: its table must hold exactly those attributes, mark exactly the ones its handler returns early without, be the table `pick_spec_table()` gives a message of its type, and put the marked attributes in at least 0.70 of the attribute streams built from it, but not in all.
- ctnetlink's `CTA_FILTER` is the one bare nest of `ct_nla_policy` that its handler parses strictly: `ctnetlink_parse_filter()` applies `nla_parse_nested()` and `cta_filter_nla_policy`, so a child whose id is past `CTA_FILTER_MAX`, 3, a nest flag on a child or a flags word of other than four bytes turns the whole request away, which is what every child drawn from the flat table, whose ids are `ct_nla_policy`'s, did. Its table, `ctnetlink_filter_attrs[]`, holds `CTA_FILTER_ORIG_FLAGS` and `CTA_FILTER_REPLY_FLAGS`, `NLA_KIND_U32_MASK` words of the twelve bits of `CTA_FILTER_F_ALL`, 0xfff, which this policy reads in host order, and `CTA_FILTER_ZONE`, a flag. A nest that passes is not yet taken: `ctnetlink_alloc_filter()` answers a nonzero flags word `-EINVAL` unless the request also carries the matching `CTA_TUPLE_ORIG` or `CTA_TUPLE_REPLY`, and parses it against those flags, and the zone flag unless it carries `CTA_ZONE`, which a mark cannot say of an attribute in another table; the flat table's draws have them by chance. `check_ctnetlink_filter()` in `tests/nfnl_gen_test.c` holds the nests to a model of the strict parse and the table to the policy.
