# net/netlink/nfnl/ — Netfilter Netlink Subsystem Grammars

## Notes
- wired by extern struct, collected by `subsystems.c`. Link-time, no path coupling.
- `nfnetlink_rcv()` runs `netlink_net_capable(skb, CAP_NET_ADMIN)` on every message before it looks at the subsystem, so every command, GET and dump requests included, is answered `-EPERM` unless both the socket's opener and the sender hold CAP_NET_ADMIN in the user namespace that owns the socket's netns. The policy parse and the handlers sit behind that test and are reached only by a child that passes it; the cthelper and osf handlers then also require `capable(CAP_NET_ADMIN)`, the initial user namespace. Subsystem files name only what is specific to them.
- `nfnetlink_rcv_msg()` and the batch path parse the top-level attributes with the liberal `nla_parse_deprecated()` against the callback's policy: an id past `attr_count` is dropped, an id in an untyped slot is accepted unchecked, and a typed slot is length-checked. A flat-table attribute the picked command's policy lacks is therefore ignored (a strict-validating genl op answers `-EINVAL`), while one whose id another namespace of the same table types differently meets that type.
- 21 of the 32 nftables commands (the NEW, DEL and DESTROY ones, marked `.batch` in `nftables_cmds[]`) are `NFNL_CB_BATCH` callbacks. `nfnetlink_rcv_msg()` answers one sent alone `-EINVAL`, after it has parsed the attributes; `nfnetlink_rcv_batch()` takes only batch callbacks of the subsystem that BEGIN names in `res_id`, answers any other message in the batch `-EINVAL`, and aborts instead of committing if any command failed. `build_nfnl_batch()` (`net/netlink/msg-core.c`) writes BEGIN, one to four batch callbacks of that subsystem and END; BEGIN carries no `NFNL_BATCH_GENID`, which the kernel would hold to the current generation.
- A scalar a policy bounds with `NLA_POLICY_MASK` or `NLA_POLICY_MAX` (the `*_FLAGS` words, `NFNLA_HOOK_HOOKNUM`, `NFTA_COMPAT_REV`) is declared `NLA_KIND_BE16_MASK`, `NLA_KIND_BE32_MASK` or `NLA_KIND_BE32_MAX`, with the policy's own mask or maximum in `max_len`; the netfilter policies read these in network byte order. `spec_fill_bounded()` (`net/netlink/msg-attr-spec.c`) draws a subset of the mask bits, or a number up to the maximum, and leaves one draw in eight random bytes so the reject arm still sees traffic. The expression policies behind `NFTA_RULE_EXPRESSIONS` hold many more such scalars, which no flat-table child targets.
- A scalar whose handler, not its policy, narrows it to a few values is declared `NLA_KIND_U8_ONEOF` or `NLA_KIND_BE16_ONEOF`, with the values in `oneof` and `n_oneof`; the kind fixes the width and byte order the handler reads it in, and `spec_fill_bounded()` picks one value and leaves one draw in eight random bytes, as for the bounded kinds. cttimeout's `CTA_TIMEOUT_L4PROTO` lists ICMP, TCP, UDP, GRE, ICMPv6, SCTP and 255, the numbers `nf_ct_l4proto_find()` has a tracker for (the GRE, ICMPv6 and SCTP ones when the kernel is built with them); NEW, DEFAULT_SET and DEFAULT_GET answer any other `-EOPNOTSUPP`. `CTA_TIMEOUT_L3PROTO` lists IPv4 and IPv6: no cttimeout handler checks it, but NEW with `NLM_F_REPLACE` and `nf_ct_set_timeout()` compare it.
- In the subsystems here a nest is a bare `NLA_NESTED`, which `nla_validate()` does not look into, except five `NLA_POLICY_NESTED_ARRAY` entries in `nf_tables_api.c` (rule, set and set-element expressions, set-desc concat, set-element list). A bare nest is parsed, if at all, by the handler: `nla_parse_nested_deprecated()` against a per-type or per-L4 sub-policy, except in ipset (and ctnetlink's `CTA_FILTER`), where the strict `nla_parse_nested()` rejects a child the sub-policy lacks. `NLA_KIND_NESTED` specs are filled as `genl/CLAUDE.md` describes, one to three children from the same flat table, so the handlers see children whose ids are outer-namespace ids.
- `tests/nfnl_gen_test.c` holds the grammars to facts about the kernel's policies, through `append_specced_nlattr()` and the registry, with no socket: ctnetlink never draws `CTA_TIMESTAMP_EVENT` (`NLA_REJECT` in `ct_nla_policy`), cttimeout lists all five of its callbacks, and a table of the top-level bounded scalars, as the kernel spells them, is declared by the grammars and drawn mostly inside its bound; so is a second table of the scalars whose handlers accept a few values, each of which must be drawn. Through `netlink_gen_msg()` it checks that a buffer opening with a batch callback is bracketed by BEGIN and END most of the time and not always, that BEGIN names nftables, that only batch callbacks sit between them, and that every batch callback opens a batch.
