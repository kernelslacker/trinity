# tables/ — Syscall Table Registry

## Files

| File | Role |
|---|---|
| tables.c | `munge_tables()` startup orchestration, `group_parent[]`, the biarch/uniarch dispatch shims, and the ASAN-only `deactivate_extrafork_syscalls()` sweep (a live ASAN run issues no EXTRA_FORK call, so those entries leave the active table; `--dry-run` keeps them) |

## Data model

- `MAX_NR_SYSCALL` is a fixed shared-memory sizing constant — NOT the same as `max_nr_syscalls`/`max_nr_*bit_syscalls`, which are the *actual* per-arch table sizes (`ARRAY_SIZE()` of the arch array). `MAX_NR_SYSCALL` bounds the shm arrays declared in `include/shm.h` (`active_syscalls[MAX_NR_SYSCALL]`, `active_cheap[MAX_NR_SYSCALL]`, `active_expensive[MAX_NR_SYSCALL]`) and the cmp_hints/kcov/minicorpus per-syscall pool dimensions (`cmp_hints.h`, `kcov.h`, `minicorpus.h` all index `[MAX_NR_SYSCALL]`). `activate_syscall_in_table()` asserts `nr_active + 1 <= MAX_NR_SYSCALL` and hard-exits if the real table ever grows past the shm cap.

## Key design decisions

2. **Biarch vs uniarch is a single runtime bool (`biarch`), not a compile split at call sites.** Nearly every public function in tables.c (`init_syscalls`, `toggle_syscall`, `dump_syscall_tables`, `display_enabled_syscalls`, `setup_syscall_group`, `deactivate_disabled_syscalls`) is a two-line `if (biarch) ... else ...` shim delegating to the arch-specific file. Only `ARCH_IS_BIARCH` (a `#ifdef`, set for x86-64) gates which set of globals (`syscalls` vs `syscalls_32bit`/`syscalls_64bit`) actually exists — `biarch` itself is set at runtime in `select_syscall_tables()`.
4. **Cost-pool bitmap is authoritative, never inferred.** `cost_pool_of()` always consults the precomputed `EXPENSIVE` bitmap, never a pool array's current membership — the comment in table-activate.c explicitly calls out that inferring from live-mutable state would let a torn pool silently "ratify" corruption instead of tripping `assert_pool_partition()`.
5. **`get_syscall_entry(callno, do32)`** (table-meta.c:513) is the universal accessor abstracting biarch away — compiled to either the direct uniarch path or the do32-branching biarch path via `#ifndef ARCH_IS_BIARCH`. Every consumer outside tables/ goes through this rather than indexing `syscalls[]` directly.
6. **`current_entry_is_*()`** (include/tables.h) read the entry cached on `this_child()->syscall.entry` (stamped by `generate_syscall_args()` before the sanitiser runs, and by `dispatch_step()`) and return a flag stamped at table-init, instead of re-running `get_syscall_entry()` plus a strcmp — called from `.sanitise`/`.post` hooks, some of which (mmap/mmap2) fire twice per call.
7. **`-x` exclusion uses a persistent flag, not a derived state.** `EXPLICITLY_EXCLUDED` is set by `toggle_syscall_n()`/`toggle_syscall_biarch_n()` and deliberately survives `deactivate_disabled_syscalls()` (which only clears `ACTIVE|TO_BE_DEACTIVATED`), so `syscall_nr_is_excluded()` can answer correctly for raw `syscall(__NR_x,...)` call sites in childops regardless of `-c`/`-r`/`-g` targeting — the file's comment documents a prior bug where inferring exclusion from `!ACTIVE` misreported non-targeted syscalls.

## Integration points

- `random_syscall/pick-common.c`, the `pick-heuristic.c` / `pick-random.c` / `pick-frontier.c` arms and `random_syscall/dispatch-step.c` — the actual runtime consumers: index `child->active_syscalls[]` (a per-child pointer set once to `shm->active_syscalls`/`32`/`64` in pick-common.c) to pick a syscall number, then call `get_syscall_entry()` and `syscall_is_expensive()` (both defined here) to resolve the descriptor and cost-pool bit
- `args/generate-args.c`, `kcov/diag.c`, `cred_throttle.c`, `main/reap.c`, `health/pre_crash_ring.c`, `health/post-mortem.c`, `dispatch/results.c`, `persist/minicorpus-*.c`, `random_syscall/chain-exec.c`, `strategy/strategy-frontier.c`, `utils/debug.c` — all call `get_syscall_entry(nr, do32bit)` to resolve a `struct syscallentry*` from a raw syscall number; strategy-frontier.c notes it deliberately bypasses this indirection on its hot path by caching the entry
- `include/shm.h` — owns the shared arrays this module maintains: `active_syscalls[32|64][MAX_NR_SYSCALL]`, `active_cheap[32|64]`/`active_expensive[32|64]`, their `nr_active*` counters, and `syscalltable_lock` (taken by `deactivate_syscall_locked()` for picker-side concurrent deactivation)
- `include/cmp_hints.h`, `include/kcov.h`, `include/minicorpus.h` — size their own per-syscall pools/rings to `MAX_NR_SYSCALL` (not `max_nr_syscalls`), the shared sizing constant this module's `activate_syscall_in_table()` guards against overflowing
- `syscall-gate.h` / `trinity_raw_syscall()` — consults `syscall_nr_is_excluded()` (table-meta.c) to turn a raw `syscall(__NR_x,...)` in a childop into an ENOSYS instead of an actual call when `-x` named it
- `include/syscalls-*.h` (one per arch) — the compile-time `struct syscalltable` literal arrays this module copies into shm; selected via `include/arch-syscalls.h`'s `#ifdef __<arch>__` chain and named via each `include/arch-<arch>.h`'s `SYSCALLS`/`SYSCALLS32`/`SYSCALLS64` macro
- `main/params/options.c` — `-c`/`-x`/`-r`/`-g` command-line flags drive `toggle_syscall()`, `enable_random_syscalls()`, `setup_syscall_group()`, all dispatched from `munge_tables()` (tables.c:235), called once after arg parsing

## Areas of attention

1. **Three parallel shm state arrays kept in lock-step by convention, not by structure.** `active_syscalls[]`, `active_cheap[]`, `active_expensive[]` (plus their `32`/`64` biarch twins — 9 arrays total when biarch) are separate `int[MAX_NR_SYSCALL]` shm fields updated together in `activate_syscall_in_table()`/`deactivate_syscall_in_table()`; `assert_pool_partition()` only catches drift by exit(EXIT_FAILURE), it can't prevent it. A bug in either function that updates one array but not another is a hard fleet-wide crash, not a silent corruption — by design (`assert_pool_partition()`'s comment explicitly rejects "silently ratify" as an option).
2. **MAX_NR_SYSCALL is a hardcoded ceiling checked against but not derived from the real table.** `include/cmp_hints.h` has `_Static_assert(MAX_NR_SYSCALL == 1024, ...)` — the value is load-bearing for shm layout elsewhere in the codebase, so bumping it (or growing an arch table past it) is a coordinated multi-file change, not a local one; table-activate.c only guards it at runtime (`exit(EXIT_FAILURE)` in `activate_syscall_in_table()`), not at compile time.
3. **biarch/uniarch duplication.** tables-biarch.c essentially doubles every uniarch function (`activate_syscall32`+`activate_syscall64` vs `activate_syscall`, etc.) rather than parameterizing over table pointers; `activate_syscall_in_table()`/`deactivate_syscall_in_table()` in tables.c already take table+counter pointers as parameters specifically to let both variants share one implementation, so the duplication is confined to the thin wrapper layer, not the core logic.
4. **`copy_syscall_table()` is the single point mutating derived per-entry fields at init** (masks, category, name-comparison booleans) — any new precomputed field needs to be added there and only there, and its zero-init assumption (`results_init_one()` stamping min>max sentinels because `alloc_shared()` zero-fills) is easy to miss if a new field also needs a non-zero "unset" sentinel.
