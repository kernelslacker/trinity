# fds/ — FD Provider Layer

Trinity's fd-supply layer. Each file (mostly) implements a "provider" that knows how to open/create one kind of file descriptor (BPF map, cgroup dir, io_uring instance, pidfd, socket, ...) and publish it into the global object pool, so `gen_arg_fd()` and the typed-fd argtypes (`ARG_FD_BPF_MAP`, `ARG_FD_SOCKET`, ...) can hand realistic fds to syscalls under test.

## Files

| File | Role |
|---|---|
| sockets.c | Socket fd provider across address families/types |
| fds-pick.c | The pickers: `get_new_random_fd()`, `get_random_fd()` (cache + retry/decay), `get_typed_fd()`, `get_pollable_random_fd()`, `get_child_live_fd()` |
| perf.c | `perf_event_open` fd provider |
| testfiles.c | Regular-file test fd pool (open/create/fcntl-state tracked) |
| fds-protected.c | Protected-fd registry: `fd_is_protected()`, `lowest_protected_fd_in_range()`, `reroll_protected_fd_arg()`, `stat_names_protected_file()` (a path can reopen a protected file under a number the registry does not know); plus `fd_relocate_high()`, the park-above-`PROTECTED_FD_HIGH_BASE` step the kcov, taint, fail-nth and rotation-sink fds share |
| files.c | Shared pool-file helpers (`open_pool_files`, `get_rand_pool_fd`) backing devfs/procfs/sysfs |
| fds.c | Provider dispatchers: fd→provider lookup, `fd_poll_can_block()`, the periodic `child_ops` / `child_init` walks, and the rate-limited `run_fd_provider_replenish()` tick, which resumes after the last provider it served |
| fds-init.c | `open_fds()` — randomized init sweep, `active_providers[]` build, enabled/initialized and per-pool-size startup logging |
| fds-param.c | `--enable-fds` / `--disable-fds` parsing (`process_fds_param`) |
| fds-registry.c | The constructor-time provider list: `register_fd_provider()`, `fd_provider_name()`, `dump_fd_provider_names()` |
| owned-fd-ring.c | `owned_fd_ring_record()` and `owned_fd_ring_retire()` (`include/owned-fd-ring.h`): the ring of fds a `.try_replenish` provider minted, or the files `ioctls/procfs-self.c` opens for its calls; closes the oldest on wrap, but only while `fstat()` still shows the file it recorded. A retire takes a number out of every provider's ring without closing it: a record retires the number it is given first, and `account_fd_and_group()` retires each number a fuzzed call returns, which `fstat()` cannot do for anon-inode files and dups |
| fds-pool.c | `pool_returned_fd()`, `pool_open_result()` and `pool_typed_fd()` (`include/fd.h`): the child's capped pool of the files a call hands back that no provider owns (an open result, the fd an ioctl cmd returns, the stream fd a bpf cmd returns), as local `OBJ_FD_TESTFILE` objects. At most `POOLED_FD_MAX` of them: a full pool destroys its oldest object (smallest `slot_version`) through the head's destructor to make room, and a head with no destructor takes nothing. An open result qualifies only as a regular file or a directory that is not a second name of a protected file. `pool_typed_fd()` is the same retire-then-publish, capped at `POOLED_FD_MAX` per type, under a typed producer's own type; what it refuses past stdio and protected numbers it closes |
| fds-diag.c | `fd_provider_init_fail()` and the last-init-reason slot `open_fds()` reads back |

## Key design decisions

1. **`struct fd_provider` is the unit of registration** (`include/fd.h`). Each file instantiates one (or a few) `static const struct fd_provider` and registers it via `REG_FD_PROV(_struct)`, a constructor-attribute macro that calls `register_fd_provider()` at load time before `main()` — no central list of providers to edit when adding a new one.
2. **Providers publish into `OBJ_GLOBAL` object pools**, keyed by a per-provider `enum objecttype` (`OBJ_FD_BPF_MAP`, `OBJ_FD_SOCKET`, ..., `include/object-types.h`). `.init()` populates the pool once at startup; `.get()` draws a fd from it. The `OBJ_GLOBAL` pools themselves only drain after init — a post-fork `add_object(OBJ_GLOBAL)` is a no-op behind the mainpid guard — so each pool's init size is its whole lifetime budget, and it is logged at startup (`fds-init.c`). Ten small-pool providers (epoll, eventfd, fanotify_init, inotify, memfd, memfd_secret, pipes, signalfd, timerfd, watch_queue) opt into the `.try_replenish` top-up hook instead, which pushes new fds straight into the child's live-fd ring via `child_fd_ring_push()`.
3. **Two fd-acquisition paths from argument generation**: untyped (`get_random_fd()` / `get_new_random_fd()`, uniform across all active non-empty providers) for plain `ARG_FD`, and typed (`get_typed_fd(enum argtype)`) for syscalls that need a specific kind — a fixed switch in `fds-pick.c` maps `ARG_FD_*` argtypes to `objecttype`s and falls back to `get_random_fd()` if unmapped or empty.
4. **`get_random_fd()` caches an fd across calls** (`child->fd_lifetime`, `RAND_RANGE(5, max_children)` reuses) to bias toward realistic fd-reuse patterns, and validates staleness via a generation counter (`fd_hash_lookup` + `cached_fd_generation`) rather than a syscall.
5. **Protected-fd registry** (`fd_is_protected()`, `lowest_protected_fd_in_range()`): keeps the child's kcov PC/CMP fds, the stderr-capture memfd, the rotation-events sink and the canary pool's directory out of the fuzz-supplied fd pool, since a fuzzed `close`/`dup2`/`ftruncate`/etc. landing on them silently kills coverage, corrupts the crash log, tears the JSONL every child shares or loses the pagecache-canary oracle its files. Consulted by `gen_arg_fd()`, the close family, size-changing sanitisers (`reroll_protected_fd_arg()`), and the two rewrites that land after a sanitiser, chain substitution and the RedQueen pin, through `rewrite_refused_slots()`. `close_range()`'s sanitiser truncates a range below the lowest protected fd it sweeps, and with EXCEPT, which closes everything outside the range, widens it to hold every one; a rewrite after sanitise could undo either, so `validate_arg_coupling()` refuses a `close_range` whose slots no longer match what the sanitiser vetted (close_range's `.vet_final` hook: chain substitution and a RedQueen pin both land after it), and the entry is not `REEXEC_SANITISE_OK`. Children also park the kcov, taint, fail-nth and rotation-sink fds above one shared base, `PROTECTED_FD_HIGH_BASE` (`include/fd.h`), out of the small numbers the pickers and mutated fd args reach, and the parent parks the canary directory there before fork; the move is `fd_relocate_high()`, which keeps the low fd when it fails.
6. **`poll_can_block` opt-in flag**: providers whose kernel `->poll` can block on an external actor (FUSE via devfs/dev_template, userfaultfd, io_uring, pidfd, seccomp_notif) tag themselves so `epoll_ctl`/`poll`/`select` sanitisers exclude them from watch sets — arming one of these under `EPOLL_CTL_ADD` can wedge the whole child in `TASK_UNINTERRUPTIBLE`, unrecoverable even by SIGKILL/watchdog.
7. **Shared pool-file helper** (`files.c`, `include/files.h`): devfs.c/procfs.c/sysfs.c are ~18-34 line wrappers over `open_pool_files(pool_id, objtype)` / `get_rand_pool_fd(objtype)` — three numbered pools (0=/dev, 1=/proc, 2=/sys), not three independent implementations.
9. **Randomized init order**: `open_fds()` opens roughly half of enabled providers in random order (`RAND_BOOL()` skip) before sweeping the rest, so provider init order isn't a fixed, guessable sequence.

## Integration points

- `args/gen_arg_scalar.c` (`gen_arg_fd`) — main untyped ARG_FD generator: 70% chance of drawing from the child's live-fd ring (`get_child_live_fd`), else `get_new_random_fd()`/typed pool, with protected-fd rerolls throughout
- `child/child-periodic.c`, `run_fd_provider_child_ops()` — every 128th op, a per-child fd-level action (bind/listen/accept, etc.) via each provider's optional `.child_ops`, skipped under `-c`/`-r`/`-g`
- `syscalls/fs/dup.c`, `syscalls/fs/fcntl.c` — pool the results of dup, dup2, dup3 and `fcntl(F_DUPFD*)` through `pool_dup_result()` (`fds/fds-dup.c`): the copy joins the `OBJ_LOCAL` pool of the fd it copies (`find_object_by_fd()`, then `publish_resource()`), and the object the returned number held is retired first (`remove_local_objects_by_fd()`); protected fds never enter a pool, on either end
- `syscalls/pidfd/pidfd_getfd.c` — pools the fd it returns through `pool_foreign_fd()` (`fds/fds-dup.c`) when `fstat()` says it is a socket (its triplet read back with `getsockopt()`) or a pipe end, and closes anything else: an anon-inode fd cannot be typed from `fstat()`
- `syscalls/fs/open.c`, `syscalls/fs/creat.c` — open, openat, openat2, open_by_handle_at and creat pool what they return through `pool_open_result()` (`fds/fds-pool.c`) when `fstat()` says it is a regular file or a directory, and close anything else: a device, a FIFO and a socket stay closed, as does a second name of a protected file. The object the number held is retired first, and a child keeps at most `POOLED_FD_MAX` of them, so a run of successful opens cannot fill the fd table
- `fds/mount.c`, `fds/fs_ctx.c` — `post_mount_fd()` (open_tree, open_tree_attr, fsmount) and `post_fs_ctx_fd()` (fsopen, fspick) pool their fd through `pool_typed_fd()` as `OBJ_FD_MOUNT` / `OBJ_FD_FS_CTX`, and coerce a refused one's retval to -1 so `register_returned_fd()` does not pool it
- `syscalls/poll/epoll_create.c` — epoll_create and epoll_create1 pool their fd the same way as `OBJ_FD_EPOLL`, recording which call made it and epoll_create1's flags
- `syscalls/ioctl.c` — `post_ioctl()` pools the nsfs fd a pidfs namespace getter returns through `pool_returned_fd()` (`fds/fds-pool.c`), and closes it when the pool will not take it. It leaves a number alone unless the cmd is a getter (`pidfd_ns_getter()`) and `fd_is_nsfs()` (`ioctls/nsfs.c`) says nsfs, and never closes a stdio or protected number
- `syscalls/bpf-prog.c` — `post_bpf_prog_stream_open()` pools the bpf-stream fd `BPF_PROG_STREAM_OPEN` returns through `pool_returned_fd()`, and closes it when the pool will not take it; a stdio or protected number is left alone. A pooled stream fd's `read()` sleeps on an empty stream unless the open set `BPF_F_STREAM_NONBLOCK`; the read's alarm ends the sleep
- `random_syscall/fd-group.c` — `account_fd_and_group()` calls `owned_fd_ring_retire()` for every fd a fuzzed call returns, so a stale ring slot cannot close the new owner of its number; a call that returns the fd it was handed (`dup2(fd, fd)`, `signalfd()` on a signalfd) retires nothing. A bounded walk of the rings, no syscall
- `stats/rotation_event.c` — owns the rotation-events sink fd (`stats_rotation_event_fd()`), the one shielded fd the parent opens and every child inherits; each child parks its copy above `PROTECTED_FD_HIGH_BASE` (60000, `include/fd.h`), like the kcov/taint/fail-nth slots
- `struct_catalog/mount.c`, `struct_catalog/bpf-*.c` — struct-field fd slots (`FT_FD`), filled by `args/struct_fill.c` from the generic fd pool
- `persist/minicorpus-field-mutate.c` — corpus replay biases ARG_FD/typed-fd argument reuse (the fd-pool cross-pollination mutator case draws from `get_random_fd()`)

## Areas of attention

1. **bpf.c (736 LOC)** builds raw `union bpf_attr` blobs across ~16 map types (`bpf_fd_types[]`) plus prog/link/btf/token providers in one file — the largest and most kernel-ABI-coupled provider; a `union bpf_attr` layout change or new map type needs updates here. A pooled map records its type and key and value size (`struct bpfobj`), which `get_rand_bpf_map()` hands the element commands of `syscalls/bpf-map.c` to size their buffers by; a map met only by id has type `BPF_MAP_TYPE_UNSPEC` and gets generous ones.
2. **scratch_block.c** manages a multi-stage, stateful kernel resource (loop device→mkfs→mount) with explicit teardown ordering — its `atexit()` parent-teardown path (unmount, `LOOP_CLR_FD`, unlink, rmdir) is best-effort/idempotent by design because partial failure is only recoverable by process exit. Loops are bound with `LO_FLAGS_AUTOCLEAR`, so the parent-held loop fd is what keeps each one bound for the run: closing it before teardown unbinds the device on its last close. A child's `LOOP_SET_STATUS(64)` replaces that flag, so `ioctls/loop.c` sets it on every such write aimed at a scratch loop's device node (matched by inode, so a dup counts).
3. **Security/isolation-sensitive providers**: scratch_block.c gates on `shm->isolation.mnt_ready` (post-`unshare(CLONE_NEWNS)` latch) before touching loop devices, so a real host disk node cannot enter the pool; cgroup.c and mount.c operate on `/sys/fs/cgroup` and mount namespaces respectively and are natural blast-radius points if the isolation gate were ever bypassed.
4. **`fds-pick.c`'s `get_new_random_fd()`/`get_random_fd()` retry/decay logic** is dense: nested inner (10-try) and outer (64, decaying to 16) retry budgets exist specifically to avoid a documented prior bug where a depleted-pool child could tight-loop burning CPU undetected by the parent's progress watchdog (the syscall record sits in PREP, before the watchdog's BEFORE-onward liveness check applies).
5. **`#ifdef`-gated providers** (bpf.c `USE_BPF`, drm.c `USE_DRM`, iommufd.c `USE_IOMMUFD`, seccomp_notif.c `USE_SECCOMP`) mean the registered-provider set varies by build config; `fds.c` code must never assume a fixed provider count.
